# 策略失效与拥挤防护

## 为什么要加防护

你提出的担心是对的：强趋势突破、财报后动量、估值修复、空头反转这些名字都不稀缺。一个策略越容易被描述、越容易被筛选器复制，就越可能因为拥挤、抢跑和交易成本而失效。

因此 Alpha Ledger 不把策略名称当作 alpha。策略名称只是候选生成器，真正能不能用，取决于它之后的真实样本表现。

相关研究背景：

- Jegadeesh 与 Titman 的动量研究说明“买赢家卖输家”这类收益模式曾经有统计基础，但这并不等于今天任何简单突破筛选器都能赚钱。JSTOR: https://www.jstor.org/stable/2328882
- Bernard 与 Thomas 关于财报后漂移的研究说明财报反应存在延迟，但实际策略仍会受到交易成本、拥挤和样本外衰减影响。JSTOR: https://www.jstor.org/stable/2491062
- McLean 与 Pontiff 研究了公开发表后收益预测因子的衰减，发现许多因子在样本外和发表后表现下降。SSRN: https://papers.ssrn.com/sol3/papers.cfm?abstract_id=2156623

## 防护原则

1. **先验降权**
   高度公开的策略默认有更高拥挤风险。比如强趋势突破的拥挤风险高于兴业科技型重估埋伏启动。

2. **样本不足不加权**
   没有足够完整 T+5/T+10/T+20 样本前，策略只能处于观察状态。单个漂亮案例不能证明策略有效。

3. **只认完整周期**
   T+10 没走满，就不能把当前涨幅算作正式 T+10 战绩。

4. **看收益，也看路径**
   策略不只看最后收益，还看最大回撤、止损率、目标命中率和盈亏比。

5. **低质量信号不入账**
   如果只有一个普通技术指标，没有明确催化、基本面映射或量价确认，就不应成为正式预测。

6. **策略可死亡**
   如果策略连续样本表现差，应降权、暂停或重写规则，而不是找借口。

## 当前实现

`python -m alpha_ledger audit --as-of 2026-05-25`

会生成每个策略的：

- 策略候选数量
- 完整 T+5/T+10 样本数量
- 平均净收益
- 净胜率
- 止损率
- 目标命中率
- 样本质量分
- 拥挤风险
- 失效风险
- Edge 分
- 健康状态

健康状态包括：

- `NO_LIVE_SAMPLE`：还没有入账预测。
- `INSUFFICIENT_SAMPLE`：样本太少，不能相信。
- `CROWDING_WATCH`：策略太公开，需要严格过滤。
- `DECAY_WATCH`：完整样本表现变差，需要降权。
- `ACTIVE_OBSERVE`：可以继续观察，但仍不是免检策略。

## 权重调整管线

审计结果不只是报告，还有自动化权重调整机制（`metrics.py`）：

- `suggest_strategy_weight_adjustments`：根据审计结果生成建议，输出 `KEEP_COLLECTING`（样本不足继续收集）、`DOWN_WEIGHT`（表现差应降权）等推荐。
- `apply_strategy_weight_adjustments`：将建议写入 `strategies.weight`，实际改变策略权重。

通过 `tune-weights` 命令触发：

```bash
# 只看建议
python -m alpha_ledger tune-weights --start 2026-04-01 --end 2026-05-15 --through 2026-05-25

# 真正写入权重
python -m alpha_ledger tune-weights --start 2026-04-01 --end 2026-05-15 --through 2026-05-25 --apply
```

## 对默认策略的态度

默认策略不是”我相信它们一定赚钱”，而是”它们有明确筛选器，能够生成可验证候选”。它们进入系统后必须竞争，不能凭名字占据权重。

下一阶段应该做两类增强：

- 用更难复制的数据提高差异化，比如机构调研文本、公告语义、供应链客户、资金结构和事件日历。
- 用更严的场景过滤降低拥挤，比如只在特定市场环境、特定行业强度、特定成交结构下启用策略。
